# 定番設定の追加・更新

## 配置

```text
presets/<用途>/README.md     用途、理由、導入・確認・更新手順
presets/<用途>/...           コピーして使う設定と最小限の動作例
parts/<設定>/README.md       複数の構成例に共通する部品（必要になったら追加）
docs/                       リポジトリ全体の方針
templates/                  構成例を記述するためのひな形
```

設定ファイルは可能な限りコピー先と同じ相対パスに置く。
説明だけの設計案、置換が必要なテンプレート、実行確認済みの構成例を区別する。
初期値にした選択と、用途によって変える選択も明記する。

## 残す内容

- 何を作るときに使うか、適用条件は何か。
- 採用ツールと、それぞれが担当するチェック。
- なぜこの構成を選ぶか、追加が必要になる条件は何か。
- コピー対象、置換する名前、依存関係のインストール方法。
- ローカルとCIで実行するコマンド。
- 確認日、確認したバージョン、実行結果、未検証の範囲。
- 更新方法と、根拠になる公式資料・参考リポジトリ。

## 検証と更新

設定の構文確認だけでなく、lint・整形・テスト・buildのうち対象に必要なコマンドを実行する。
必要なら最小限の動作例を添え、接続・配布などの境界も確認する。
検証に外部アカウントや公開操作が必要なら、実行していない範囲を具体的に残す。

公式の一次資料を確認し、依存関係とlockfileを同じ変更で更新する。
自動生成のlockfileは生成ツールを使い、手書きしない。
参考リポジトリはコミットを記録し、そこでの設計から何を採用したかを説明する。

構成例の変更を、そのまま参照元リポジトリの変更やリリースまで広げない。
利用者が新しいリポジトリに持ち込んだ際の設定変更・権限・公開操作は、導入手順に記載する。
